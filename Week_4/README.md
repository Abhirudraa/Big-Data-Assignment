# Week 4 – Customer and Transaction Data Analysis using Google Cloud Dataproc

## 1. Project Overview

This assignment demonstrates large-scale data processing using **Google Cloud Dataproc and PySpark DataFrame API**.

The objective is to process customer and transaction datasets, clean invalid records, standardize data, join the datasets, and generate useful business aggregations.

All Spark processing was executed on a Google Cloud Dataproc cluster. No local Spark execution was used.

## 2. Utility of Each Included File

### `main.py`
The main PySpark application containing the complete data-processing workflow.

It performs the following operations:

- Reads customer and transaction CSV files from Google Cloud Storage.
- Inspects and validates the input schemas.
- Identifies missing values, invalid records, and duplicate rows.
- Cleans and standardizes customer information, including city names.
- Validates transaction dates and amounts.
- Checks referential integrity between customer and transaction records.
- Creates transaction categories: Low, Medium, and High.
- Extracts the transaction month.
- Joins customer and transaction datasets.
- Calculates customer-wise and city-wise transaction summaries.
- Identifies the top three customers by total transaction amount.
- Saves cleaned datasets, invalid records, joined data, and aggregations to Google Cloud Storage.

The application uses the PySpark DataFrame API and does not use SparkSQL.

### `output/cleaned_data/customers/`
Contains the cleaned customer dataset.

- Invalid and duplicate customer records are excluded.
- Customer IDs and names are trimmed.
- Status values are standardized.
- City names are normalized, for example, `TRIVANDRUM` and `Trivandrm` become `Trivandrum`.

### `output/cleaned_data/transactions/`
Contains valid and cleaned transaction records.

- Transaction IDs and customer IDs are validated.
- Transaction amounts are converted to numeric values.
- Transaction dates are validated and converted to the appropriate date type.
- Payment mode values are standardized.
- Transactions with invalid or missing mandatory fields are excluded.

### `output/invalid_rows/customers/`
Contains customer records rejected during cleaning, along with an `invalid_reason` column explaining why each record was rejected.

Reasons include missing mandatory fields and duplicate records.

### `output/invalid_rows/transactions/`
Contains invalid transaction records, including records with missing fields, invalid dates, non-positive amounts, duplicate rows, or customer IDs that do not exist in the cleaned customer dataset.

### `output/joined_data/`
Contains the combined customer and transaction dataset.

The cleaned datasets are joined using `customer_id`. The resulting dataset also includes the derived transaction category and transaction month.

### `output/aggregates/customer_summary/`
Contains customer-level transaction statistics:

- Total transaction amount per customer.
- Average transaction amount per customer.

### `output/aggregates/city_summary/`
Contains the total transaction amount grouped by standardized city.

This output helps compare transaction activity across different cities.

### `output/aggregates/top_3_customers/`
Contains the three customers with the highest total transaction amounts, including their customer IDs, names, total amounts, and average amounts.

### `part-*.csv`
These are the actual CSV data files generated by Spark inside each output directory. Spark writes its output as part files rather than necessarily creating a single named CSV file.

### `_SUCCESS`
A marker file automatically generated by Spark to indicate that the corresponding output-writing operation completed successfully. It does not contain business data.

## 5. Execution Workflow

1. Configured the Google Cloud project in Cloud Shell.
2. Enabled the required Google Cloud APIs.
3. Downloaded the customer and transaction datasets.
4. Uploaded both CSV files to the Cloud Storage input directory.
5. Created the Dataproc cluster.
6. Submitted `main.py` as a PySpark job to Dataproc.
7. Dataproc executed the data-cleaning, transformation, joining, and aggregation operations.
8. Verified the job execution status and driver output.
9. Verified the generated output directories in Cloud Storage.
10. Downloaded the generated output files for submission.
